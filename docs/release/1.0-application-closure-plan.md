# FeedMine 1.0 — Application Closure Plan

**Created:** 2026-09-28  
**Starts after:** Runtime V2 Phase 2 static closure  
**Purpose:** finish the shipping application without reopening Runtime V2 architecture.

## A. Build and configuration gate

- Treat iOS 18.0 / Swift 6 as the declared minimum/toolchain contract.
- Keep `Info.plist` version/build authoritative (`1.0`, build `17` at this baseline); increment build only for an actual archive candidate.
- Verify Release configuration resolves the same package versions as the project.
- Verify every source/resource added by the Runtime V2 work is in the intended target and no test/probe target is embedded in the app.
- Prepare archive validation commands; execution remains pending until Xcode is available.
- Do not add GitHub Actions.

## B. Launch and mode closure

- Make the production launch mode explicit and deterministic.
- Debug/test arguments may select legacy/shadow/presentation modes; a distribution build must not accidentally inherit a developer override.
- Preserve the kill switch/rollback mode until the compatibility window is formally closed.
- Ensure a runtime database open/migration failure fails safely to the documented compatibility behavior and produces a useful local diagnostic.

## C. Product-surface closure

- Main Feed and Bookmark Box: Runtime V2.
- Canonical Content Search: Runtime V2 index + user-state overlay.
- Compatibility surfaces: Last Clicked, Source Collection, Smart Feed, Source Detail, Saved Search, Onboarding.
- No-view plumbing: Persistent Search and What's New do not become release blockers.
- Verify every compatibility surface is usable offline from retained content and cannot start duplicate feed acquisition in `v2Full`.
- Remove or hide any UI affordance whose implementation is knowingly non-functional in the shipping configuration; do not ship dead buttons.

## D. Data, upgrade and recovery

Prepare/execute when Apple environment exists:

- clean install;
- upgrade from supported build-17 container;
- runtime DB migration;
- user.sqlite/bookmark preservation;
- OPML/import preservation;
- crash at Admission and Publication/media boundaries;
- low/disk-full recovery;
- corrupt runtime DB quarantine/rebuild without deleting user authority;
- offline warm restore;
- rollback mode.

## E. Privacy and platform declarations

Static baseline:

- privacy manifest declares no tracking and no collected data;
- required-reason API declarations exist for UserDefaults and file timestamps;
- non-exempt encryption is declared false;
- background identifiers/modes are declared;
- arbitrary media transport exception is scoped to media.

Before archive submission, audit source use against the privacy manifest and App Store privacy answers. The
manifest is not proof by itself; any SDK/new API use added after this baseline must be reconciled.

## F. Localization and accessibility

- Validate the string catalog parses and the languages declared in `CFBundleLocalizations` have intentional coverage.
- Missing translations may fall back to the development language; malformed placeholders/plurals are blockers.
- Smoke the primary paths under RTL and large Dynamic Type.
- Verify VoiceOver labels for navigation, cards, bookmark controls, search and media controls.
- No release blocker is created merely because all 40 locales are not linguistically perfect; crashes, clipped navigation and unusable controls are blockers.

## G. App Store package

External/manual artifacts to prepare outside code where necessary:

- app name/subtitle/description/keywords;
- privacy-policy URL and support URL;
- screenshots for required device classes;
- age rating/content declarations;
- copyright;
- review notes explaining RSS/Atom network access and optional background/audio behavior;
- export-compliance answer consistent with `ITSAppUsesNonExemptEncryption=false`.

Repository-side archive candidate checklist:

1. clean working tree / known commit;
2. Release archive;
3. validate archive;
4. install archive/TestFlight build on physical device;
5. execute the Runtime V2 release evidence checklist;
6. only then increment/freeze the submitted build number if needed.

## H. Final static audit

Search the shipping target for:

- `fatalError`, `preconditionFailure`, forced unwraps/casts on external data;
- TODO/FIXME markers on reachable release paths;
- unbounded Tasks/timers/retry loops;
- direct renderer network;
- duplicate acquisition entry points bypassing `LegacyAcquisitionGate`;
- stale feature flags;
- test/debug menus or developer URLs;
- hard-coded secrets/credentials;
- unsupported URL schemes;
- writes from views that bypass the user-state/session boundaries.

Classify each finding as blocker, compatibility debt, or post-1.0 cleanup. Fix blockers; document the rest.

## Definition of application-complete

FeedMine 1.0 is application-complete when:

- no known static release blocker remains;
- runtime/compatibility ownership is explicit for every shipping surface;
- prepared automated tests compile and pass in the Apple environment;
- physical-device release evidence is recorded;
- clean-install and real-upgrade rehearsals pass;
- privacy/localization/accessibility audits have no blocker;
- an archive candidate can be validated and installed;
- App Store metadata/manual submission artifacts are the only remaining work outside the repository.
