## Context

Today the app has no exposure interval: it has a visibility boolean and three independent string sets, so "was this card actually read into view" cannot be answered, re-entry and rerender are indistinguishable, and the exclusions derived from those sets are applied uniformly to every surface. The repo facts that force this decision:

- `feedmine/Views/FeedScreen.swift:887-891` registers `.onScrollVisibilityChange(threshold: 0.5) { if visible { loader.markAsSeen(item.id) } }` — a fraction threshold with no dwell, so a 60 ms fling through a card grants the same fact as a card held for a minute, and the fact is written on the *entry* edge only.
- `feedmine/Views/FeedScreen.swift:892-895` additionally treats `onAppear` as the position signal and as the replenishment trigger (`loader.noteVisibleIndex(for: item)` then `Task { await loader.loadMoreIfNeeded(currentItem: item) }`), which Blueprint §15 and invariant I-20 forbid; `onAppear` also fires on rerender, which is precisely the false-exposure case Blueprint §19 names.
- `feedmine/Services/FeedLoader.swift:614-629` defines `noteVisibleIndex(_:)` / `noteVisibleIndex(for:)` as an index hint deduplicated by a single `_lastNoteVisibleID` string and resolved through `filteredItems.firstIndex(where:)`; the value is an array position in the current filtered list, not a publication identity, and the `guard let` fallback silently drops the observation when the item is not in the filtered list (the comment calls this a trim/load-more anchor concern).
- `feedmine/Services/FeedStore.swift:955-958` holds `readItemIDs`, `consumedItemIDs`, `clickedItemIDs`, `clickedSourceURLs` as four `Set<String>` keyed by legacy `FeedItem.id`, and `feedmine/Services/FeedStore.swift:3856-3858` writes `consumedItemIDs` and `clickedItemIDs` together in one function, so the distinct facts this ADR separates are already collapsed in the write path.
- The exclusions are global, not per surface: `feedmine/Services/FeedStore.swift:604-609` and `feedmine/Services/FeedStore.swift:847-852` gate visibility on `includeConsumed || isClickHistory || isSmartFeed || !consumedIDs.contains(item.id)`, and `feedmine/Services/FeedStore.swift:4217` passes `includeConsumed: false` for collection publication. Seen-in-Main therefore removes cards from Collection, and `feedmine/Services/FeedStore.swift:828-838` can only patch this for Smart Feeds by re-ordering consumed rows to the tail.
- Persistence is per item and unbounded in cardinality: `feedmine/Services/FeedStore.swift:3818-3831` writes one `UPDATE feed_item SET consumed_at = ...` per seen card on its own `Task`, never in a batch, and `feedmine/Services/FeedStore.swift:6146-6160` reloads the full read/consumed/clicked sets at startup as `SELECT id FROM feed_item WHERE ...` with no bound.
- Reversibility is already partly decided in the repo and must be carried forward: `feedmine/Services/FeedStore.swift:3952-3955` clears `is_read` on "mark unread" while keeping `consumed_at`, with the comment that unread "never requeues an already seen card".

## Decision

**D1 — An exposure interval is a continuous foreground dwell of at least 50% of the card's area for at least 1000 ms.** Both knobs (`minVisibleFraction`, `minDwellMs`) are configuration, not constants, and every fact records the `policy_version` that produced it. The initial values are hypotheses to be tuned; changing them creates a new policy version and does not rewrite facts recorded under the old one. `seen` is granted exactly when the interval's credited dwell reaches the threshold while the visible fraction remains at or above the threshold; shorter or smaller intervals grant nothing.

**D2 — Viewport observations are coalesced UI telemetry, not a queue.** The UI submits `ViewportObservation` values (Blueprint §14 `submitViewport(_:)`); the tracker samples and coalesces at 50–100 ms (Technical Architecture §55, `bufferNewest(1)` semantics) and derived arithmetic uses an injected monotonic clock, never `Date()`. Coalescing may drop intermediate samples but must not lose a *state transition*: an entry edge, a threshold crossing, a threshold-satisfaction completion, or a left-viewport edge is retained even if the sample that produced it is superseded immediately.

**D3 — Exposure continuity is anchored to `PublicationCardID`, not to the SwiftUI view, and a rerender is not part of the interval's life.** The interval opens on a viewport entry observation for a card and closes only on a left-viewport observation, a lifecycle end, or an edition swap. View-level `onAppear`/`onDisappear` caused by rerender, window eviction and re-materialization, image materialization, or a render-environment change produce no fact and do not restart credited dwell (Blueprint §19; I-14, I-15). Rerender does not *credit* dwell during a gap either: credited dwell is the time between the last coalesced sample and the interval start, so a rerender that removes geometry for longer than `coalesceWindowMs` closes the interval through the window-eviction path in D4 rather than silently continuing.

**D4 — Window eviction and restoration have one defined rule.** Eviction alone produces no fact. If a card is evicted while its last known visible fraction was at or above the threshold, the interval is closed with `reason = windowEvicted` and dwell credited only up to the last coalesced sample before eviction; if the card is re-materialized at the same edition, `cardID` and ordinal anchor within `coalesceWindowMs`, that materialization continues the same visit (no new `visit_ordinal`, no gap), otherwise it is a new visit per D11.

**D5 — Every fact type is recorded separately and none is inferred from another.** The semantic facts are `seen`, `opened`, `read`, and `bookmarked`/`bookmarkRemoved`; the interval-geometry events are `viewportEntered` and `viewportLeft`; the weak crossing event is `centerCrossed`. `centerCrossed` is recorded when the card's center passes the viewport center in either direction, and it is deliberately *weaker* than `seen`: a fast fling may log `centerCrossed` repeatedly while granting no `seen`. `opened` is recorded by an explicit primary-action invocation (Blueprint §101) and does not by itself imply `read`; `read` requires an explicit reader session or an explicit user mark; `bookmarked` is an intent fact owned by `user.sqlite` per ADR-004 and mirrored into history as an overlay, never as an exclusion.

**D6 — Opening or actioning a card never blocks navigation on a history write.** `opened` and its history projection are written through the coalesced exposure channel; the UI presents the reader immediately (Blueprint §101; plan §19 additional decisions).

**D7 — Every fact type has one explicit idempotency key, and one row is authoritative.** The key is the canonical `fact_key` string below; `UNIQUE(fact_key)` is the deduplication. Replaying the same key (crash before acknowledgement, double flush, re-delivered observation) is a no-op and must not increment supply, projections, or counters.

| Event type | Idempotency key (`fact_key`) | Revisit allowed |
|---|---|---|
| `viewportEntered`, `viewportLeft`, `seen` | `edition:<edition_id>\|card:<card_id>\|scope:<scope>\|ref:<scope_ref>\|visit:<visit_ordinal>\|event:<type>` | yes, via a new `visit_ordinal` |
| `centerCrossed` | same as above plus `\|dir:<direction>` | yes |
| `opened` | `edition:<edition_id>\|card:<card_id>\|scope:<scope>\|ref:<scope_ref>\|event:opened` | no, once per edition |
| `read`, `bookmarked`, `bookmarkRemoved` | `card:<card_id>\|event:<type>\|source:<user_state_op_id>` | no, the durable user-state operation id is the key |

**D8 — Revisits are bounded, ordered and do not make `seen` non-idempotent.** A visit is a maximal contiguous exposure interval for a card; `visit_ordinal` starts at 0 for the first interval of a card within an edition and increments per new interval, ordered by interval start. A re-entry is a new visit only if the card was closed per D3/D4; re-entry inside `coalesceWindowMs` continues the current visit. Each visit may produce its own `centerCrossed`/`seen` fact, but the `seen` *projection* per (scope, card) is idempotent: writing `seen` twice for the same scope and card updates a timestamp, never a count.

**D9 — Facts are persisted at milestones and by debounce, never per frame.** The baseline flush policy is 20 facts or 500 ms, whichever comes first, plus an explicit flush on lifecycle transition, on interval close, and on session end (Technical Architecture §74). These are also versioned policy knobs. Unconfirmed work is the only thing a crash may lose: dwell accumulated since the last flush is dropped, and nothing persists an interval whose `seen` threshold was never observed before the last flush. A crash never invents an exposure, never fabricates a left-viewport timestamp, and never partially writes an interval (interval facts for one visit are flushed in one transaction). Exposure writes travel through the non-critical write coordinator (Technical Architecture §75) and are never mixed into Admission, Publication, checkpoint, or durable user-action transactions.

**D10 — History is bounded, and the bound never touches the projection that policy reads.** The detailed fact log is retention-bounded (see the OPEN item on quota, ADR-004). The per-scope `seen`/`opened`/`read`/`centerCrossed` projection keys are durable user state and a retention root (Technical Architecture §83): evicting old facts may drop interval detail, never the fact that a card was seen/read on a surface. Recomputing a projection from a pruned fact log is not permitted to *reduce* it; projections must be recomputed only from surviving facts and otherwise left intact.

**D11 — Stale work cannot attach to history.** A late flush carrying an `edition_id` that is no longer the active or checkpointed edition, or a session stamp older than the current session, is rejected without writing any fact or projection, and cannot be associated retroactively with a record or card (plan §19 row 32). The only permitted residue is content-addressed orphan media and non-sensitive rejection counters (ADR-004, ADR-006).

**D12 — `HistoryScope` is explicit per surface, owned and versioned, and Main's discovery exclusion is not global.**

| Surface | `seen` applied (excluded from supply) | click/read overlay shown | card auto-excluded | policy/version owner |
|---|---|---|---|---|
| Main (discovery) | Yes — cards seen in Main are excluded while `applySeen = true` | Yes, overlay stamped on the card | Yes, but only by the Main scope's own `seen`/consumed projection | `MainFeedPlan` policy bundle + `history_policy(scope='main')`, version in `EditorialRevision` (ADR-002) |
| Source | No — Source keeps a navigable history of its own cards regardless of Main's discovery `seen` | Yes | Only by an explicit Source-scope exclusion policy; never inherited from Main | Source-scope policy + `history_policy(scope='source')` |
| Bookmark | No — the saved list survives `seen`, `opened` and `read` unconditionally | Yes | Never; removal only by explicit user deletion | `user.sqlite` bookmark authority (ADR-004); runtime mirrors, never filters |
| Search | No — an item is not dropped because it appeared in Main | Yes | Only by explicit user filters (`source enabled`, content filters); never by `seen` | Search plan policy + `history_policy(scope='search')` |
| Collection | Declared per collection (default: same as Source, `applySeen = false`) | Yes | Declared per collection, with version | Collection policy revision + `history_policy(scope='collection', ref=<id>)` (ADR-002 fingerprint input) |
| Smart Feed | Declared per Smart Feed; consumed ordering may keep items but must not remove them | Yes | Declared per Smart Feed, with version | Smart Feed policy revision + `history_policy(scope='smartFeed', ref=<id>)` |

Two rules ride on this matrix: a durable `clicked`/`read` fact may appear as an overlay on *any* surface without auto-excluding the card, and a surface that declares `applySeen = false` must still be able to display `seen` as an overlay.

**D13 — Exhaustion and degradation are states, not history mutations.** When a scope has no fresh supply, the session reports `exhausted`/`degraded`, keeps the retained history navigable, retries with a bound, and does not loop the same cards as new, does not re-emit them as unseen, and does not erase the consumed projection (plan §19 row 37).

**D14 — Deletion and tombstones project into history, and never rewrite it.** An upstream delete/revoke moves an `OriginRecord` to a future-facing availability state (Blueprint §§43-44) and changes eligibility and presentation only; exposure facts, dwell, and projections for already-published cards remain, and published history is not mutated (I-09). Forced removal of a *publication* is an explicit `PublicationOverlayPolicy` (ADR-001) recorded as a policy event; physical purge is a distinct authorized operation (ADR-004). History reads apply the overlay at read time so that a revoked card cannot be re-shown from a projection, while the underlying fact remains auditable.

**D15 — Monotonic time is scoped to a boot session.** `observed_at_ms` is monotonic device uptime milliseconds plus a persisted `boot_session_id` minted when the runtime first observes an uptime reset; `wall_clock_ms` may be recorded for diagnostics only and is never used for dwell arithmetic or ordering. Arithmetic across two different `boot_session_id` values is invalid and must be rejected, which bounds clock-skew and manual-clock-change damage.

## Rejected alternatives

- **Keep the boolean `seen` written on the 0.5-threshold entry edge (`FeedScreen.swift:887-891`).** Rejected: it cannot distinguish a fling from a read, cannot express revisits, has no interval to close, and has no policy version to attribute a fact to.
- **Grant `seen` from `onAppear` / cell lifetime.** Rejected by Blueprint §19 and I-15: rerender, image materialization and window restoration all fire appear/disappear without the card being visible, so this fabricates exposure and, in the current code, collides with the replenishment trigger and I-20.
- **One history table with a nullable `read_at`/`clicked_at`/`bookmarked_at` per card and per-surface boolean filters.** Rejected: it collapses facts (the defect at `FeedStore.swift:3856-3858`), cannot store an interval with dwell and direction, and forces the same exclusion onto every surface, which is exactly the bug the HistoryScope matrix removes.
- **Count dwell per frame in the view and POST the final number from the view on disappear.** Rejected: the view cannot survive eviction, cannot coalesce, and would have to persist per frame; Blueprint §§14-16 keep viewport as telemetry and Technical Architecture §73 keeps the tracker outside SQLite per frame.
- **Treat `centerCrossed` as sufficient for `seen`.** Rejected: it would make a fast fling mark arbitrary numbers of cards as seen, permanently hiding them in discovery.
- **Unbounded exposure log with projections computed on demand.** Rejected: unbounded growth in the runtime database contradicts Technical Architecture §83, and on-demand projection from a pruned log would silently reduce `seen`/`read`.

## Schema and types

Owned by this ADR; physical types of `feed_edition.edition_id` and `origin_record_id` follow ADR-001/ADR-003. Runtime database is `runtime-v2.sqlite` (plan §6), WAL, foreign keys on.

**Interval state machine.** States per (card, edition, visit): `absent → open → credited → closed`. Credited dwell is always computed against the interval's start and the last coalesced sample, never against wall clock or a view lifetime.

| Event | Precondition | Effect on interval state | Persisted |
|---|---|---|---|
| viewport entry / restored materialization at same anchor inside `coalesceWindowMs` | no open interval, or closed interval whose close is a same-anchor window eviction | `absent → open` (new `visit_ordinal`) or continue current visit | `viewportEntered` (flushed with the interval batch) |
| coalesced sample with `visibleFraction >= minVisibleFraction` | `open` | keep `open`, update `maxVisibleFraction` | nothing per sample |
| credited dwell reaches `minDwellMs` while fraction holds | `open` | `open → credited`; emits `seen` once per visit | `seen` with `dwell_ms`, `max_visible_fraction`, `policy_version` |
| card center crosses viewport center | card materialized, any state | no state change; `centerCrossed` recorded with direction (may repeat) | `centerCrossed` |
| coalesced sample with `visibleFraction < minVisibleFraction` | `open` or `credited` | close interval, credit dwell up to the last sample | `viewportLeft` with `close_reason='leftViewport'`, `dwell_ms` |
| card evicted from window with last known fraction at/above threshold | `open` or `credited` | close interval, credit dwell up to the last sample | `viewportLeft` with `close_reason='windowEvicted'` |
| scene phase leaves foreground / interruption / explicit session end | any | close all open intervals for the session | `viewportLeft` with `close_reason='background'` or `'sessionEnd'` |
| active edition swap | any | close all open intervals of the previous edition | `viewportLeft` with `close_reason='editionSwap'` |
| SwiftUI view `onAppear`/`onDisappear` from rerender, image materialization, render-environment change | any | **no state change** | nothing (I-15) |
| explicit primary action (open) | card exists in the active edition | no state change | `opened` (coalesced channel; never blocks the reader) |
| explicit mark read / mark unread | durable op id present | no state change to intervals; `read_cleared_at_ms` set on unread | `read` / projection clear |
| flush trigger (20 facts, 500 ms, interval close, lifecycle) | there are unconfirmed facts | unchanged | all facts of one visit in one transaction |

**OPEN items in this ADR's scope:**
- **OPEN-1 — physical type of `publication_card_id`/`edition_id`.** This ADR writes `INTEGER` for the card and `TEXT` for the edition; ADR-003 (identity encoding) and ADR-001 (`feed_edition`) must confirm or amend before PR-07.
- **OPEN-2 — fact-log retention quota.** The bounded-fact-log policy (bytes / age / fact count, and whether detail is pruned per scope or globally) needs measurement and belongs to ADR-004 (quota) with ADR-007 owning the *rule* that projection keys are never pruned (D10).
- **OPEN-3 — `history_policy` key shape.** Whether policy is stored as one row per scope with a JSON value or one row per (scope, key) must match the policy-bundle representation ADR-002 fixes for `EditorialRevision` fingerprints.
- **OPEN-4 — reader dwell.** `read` here means an explicit reader session or explicit user mark; whether reader dwell is itself recorded as a separate fact (and with which policy) belongs to the Interaction surface in ADR-001/ADR-002, not to feed exposure.
- **OPEN-5 — D1 tuning values.** 50% / 1000 ms are the initial hypothesis; the acceptance thresholds after tuning are a measured decision and must be recorded as a new `policy_version`, never edited into a historical row.

## Invariants

1. **H-01** — No `seen` row exists with a `dwell_ms` below the `min_dwell_ms` of its own `policy_version`. (I-15, exposure rule D1/D9; no Technical Architecture id)
2. **H-02** — No exposure fact exists for a card that was not materialized in the active edition with a viewport observation of that card. (I-15)
3. **H-03** — Rerender, image materialization, window restore, and render-environment change produce zero rows in `exposure_fact`. (I-14, I-15)
4. **H-04** — Exposure identity is `PublicationCardID`; no row stores a view index, array offset, or `FeedItem.id` as identity. (I-14)
5. **H-05** — Over a session, credited `dwell_ms` for a visit never exceeds the monotonic elapsed time between that visit's entry and close, and never counts time when the app was not in foreground. (D1, D3, D15)
6. **H-06** — Credited dwell is quantized by the coalescing window: `dwell_ms` equals the last coalesced sample time minus the interval start, so the same observation sequence yields the same dwell regardless of frame rate. (D2, D3)
7. **H-07** — `UNIQUE(fact_key)` holds for every fact type in D7; replaying any flush produces no new row and no projection change. (D7, D9)
8. **H-08** — A `seen` projection per (scope, scope_ref, card) is idempotent: a second visit updates `last_seen_at_ms` and increments `visit_count`, and never duplicates an exclusion. (D8)
9. **H-09** — No card is excluded from a surface whose `apply_seen = 0` because of a `seen` fact recorded in another scope. (D12)
10. **H-10** — Bookmark-resident cards are never removed by `seen`, `opened`, or `read`; only an explicit user deletion changes that list. (D12, I-16)
11. **H-11** — Search results are never dropped because the same `PublicationCardID` (or origin) was seen in Main. (D12)
12. **H-12** — Pruning the fact log never deletes a `history_projection` row that policy reads. (D10, I-16)
13. **H-13** — A flush whose `edition_id` is neither active nor checkpointed, or whose session stamp predates the current session, writes zero rows. (D11)
14. **H-14** — A crash between flushes may lose only facts never flushed; after restart, no fact exists whose interval was not observed, and no interval is credited beyond its last flushed sample. (D9)
15. **H-15** — Upstream deletion/revocation adds no fact and removes none; presentation changes only through the declared overlay. (D14, I-09)
16. **H-16** — Viewport submission performs no acquisition: no `GET`, no cursor advance, no `loadMore`, and no exposure flush performs Admission, Publication, checkpoint, or durable user-action writes. (I-01, I-20)
17. **H-17** — `opened` is recorded without blocking the reader presentation and without blocking card navigation. (D6, Blueprint §101)
18. **H-18** — Session restore reads `session_checkpoint` and `history_projection` only; it opens no network and runs no Selection when a compatible edition is checkpointed. (I-16, Blueprint §96, Technical Architecture §82)

## Edge cases

- **Crash between flush and acknowledgement.** Replayed flush hits `UNIQUE(fact_key)`; projections must not double-count `visit_count` (the projection update is keyed by the same fact key).
- **Monotonic clock reset (reboot) mid-interval.** Interval arithmetic spanning two `boot_session_id` values is invalid: the interval is closed at the last sample of the old boot session, dwell credited up to it, and no `seen` is granted if the threshold was not reached (D15).
- **Manual clock change / timezone change.** No effect on exposure: `wall_clock_ms` is diagnostic only.
- **Fast fling through many cards.** Any number of `centerCrossed` facts, zero `seen`; the coalescing window may collapse intermediate `centerCrossed` entries but must retain at least one per crossing edge (D2, D5).
- **Rerender while a card is at/above threshold.** No fact, no interval restart, dwell continues from the interval start (D3).
- **Window eviction while a card is being dwelled, then restoration at the same anchor.** One visit, credited dwell includes the eviction gap only if restoration occurs inside `coalesceWindowMs`; otherwise the gap is not credited and a new visit starts (D4).
- **Background/kill/lock during an interval.** Interval closes as `background`; credited dwell is the last coalesced sample, so a partially dwelled card does not become `seen` unless the threshold was already reached and flushed (D3, D9).
- **Two sessions on the same surface (e.g. Main and a Source view showing the same card).** Facts carry their scope; the `seen` projection per scope is separate, so the discovery exclusion does not leak into Source (D12, H-09).
- **Same card published in a successor edition.** New edition means a new interval namespace; `visit_ordinal` restarts, and projections record the newest edition while keeping the older fact rows (D8, D14).
- **Card whose origin was tombstoned/revoked after being seen.** Facts survive, presentation is suppressed by overlay at read time; restore must not resurrect the card through a projection (D14).
- **Persistence failure / disk full during flush.** The flush fails as a unit, increments a rejection counter, and retries at the next milestone; it never writes a partial interval and never blocks UI (D9, D11).
- **No supply after refresh.** Session reports exhaustion; history stays navigable; a bounded retry does not re-publish consumed cards as new and does not erase the projection (D13).
- **Migration.** A schema change to `exposure_fact` requires a deterministic migration; an unknown future schema must fail controlled rather than be interpreted permissively, and old facts keep their `policy_version` (plan §6, §19 additional decisions on `PublicationSchemaVersion`).
