# Crash e robustez — feedmine

Alvo: app `feedmine/` + pacote `Packages/FeedRuntimeV2/Sources`. Branch `fix/release-1.0-final-hardening`, HEAD `70f7b06b`.
Somente leitura. Cada achado foi verificado por leitura direta do arquivo (linha citada).
Todos os caminhos são relativos à raiz do repositório `/Users/wagnermontes/Documents/GitHub/feedmine`.
Severidade: BLOQUEADOR (crash/perda de dado/segurança) · ALTO (bug visível ou esgotamento de recurso) · MÉDIO · BAIXO.

Alcance dos achados do pacote: o Runtime V2 completo (`v2Full`) é **opt-in** — `RuntimeModeLaunch.decide` cai em `legacy` quando não há pedido persistido (`feedmine/RuntimeV2/RuntimeMode.swift:114-119`). `PolicyEnforcingHTTPTransport`/`FeedConnectorSyndication`/`FeedStorage`/`FeedSession` só executam nesse modo. `FeedMedia` (`MediaPreparation`, `ImageBroker`) **não é referenciado por `feedmine/`** (grep vazio): os itens CR-06/CR-07 e CR-25 são latentes, não vivos no app de hoje.

- CR-01/CR-02 são os únicos alcançáveis **por feed** no caminho de produção padrão (modo legacy) sem servidor hostil: basta um `<itunes:duration>` grande (FeedKit `String.toDuration()` em `.build-dd/SourcePackages/checkouts/FeedKit/Sources/FeedKit/Extensions/String + toDuration.swift:33-52` soma `Double(e) * pow(60, i)` sem teto).
