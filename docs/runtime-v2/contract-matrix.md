## 4. How a row changes

Changing a frozen contract requires, in the same reviewable set: the ADR amendment, a compatible migration, the test that encodes the new behaviour, and every consumer of the contract. Until the freeze is approved, the ADRs are drafts and this table is a proposal — not a licence to skip the ADR.

## 3. How this matrix was validated

Test names are not decoration here, they are the traceability claim, so they are checked against the tree rather than trusted — and the **method** is what makes the number mean anything.

First pass (PR-14) searched each of the 40 names with `grep -rl` and found 38 resolving. That method is too weak: `grep -rl` matches a **mention**, so a name cited only in a doc comment would count as present. It nearly did — row 36's name (`purposeBudgetStopsAcquisitionWithoutLosingCheckpoint`) appears in the doc comments of `RunwayControllerTests.swift:526` and `AcquisitionCoordinatorTests.swift:328`, and only the second pass distinguished that from an actual test.

Second pass (PR-15) requires a **function definition**: for each row, `grep -rniE 'func\s+test.*<name>'` across `Packages/FeedRuntimeV2/Tests` and `feedmineTests`. Result:

| Outcome | Count |
|---|---:|
| Resolves to a `func test…` definition | **39** |
| Named only in a doc comment or mention | **0** |
| Absent entirely | **1** |

**Every name in this matrix now resolves to a test.** The last absence, row 33's `evidencePurgePreservesBookmarksAndHistory`, was written by PR-16 together with the retention coordinator and the durable account (`retention_policy`, `gc_run`, `gc_run_class`) it needed; the Status column above records what the test asserts. The 40 decisions are therefore all backed by a named test that exists, not by a name that only exists.

One naming mismatch was found and fixed in the first pass and is worth repeating as a caveat: the rows use the plan's proposed names, while the implemented functions often carry prose names (`testARefillThatStopsOnItsBudgetKeepsItsCheckpoint` for row 36's intent), and case must match (`MainExposureDoesNotHideBookmarkOrSourceHistory`, not `mainExposure…`). A future reader grepping a row's name should therefore expect to find either an exact function or a doc comment naming the matrix row, and should treat only the former as proof.
